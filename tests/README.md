# tests/ — 町づくり(vil-core / vil-ui)の確認スクリプト

【状態】5g 版までは GitHub(`feature/vil-storage`)に保存済み。この README は 5h 版への更新(**未アップロード**。ユーザーが確認後に手動でアップロード)です。

## 目的
作業環境の入れ替えでテストが消えるのを防ぐため、確認スクリプトとその実行結果をリポジトリで管理する。

## 必要な環境
- Node.js 22 以上、`npm i`（playwright は **1.63.0 に固定**）、`npx playwright install chromium`
- `package-lock.json` は、5f・5g・5h とも Claude の作業環境から npm レジストリへ接続できず**未生成**です。作り方は `PACKAGE_LOCK_GUIDE.md`(Windows・初心者向け)を見てください。
- Linux / macOS。ブラウザは Chromium(Playwright)。**実機のスマホでは未確認**(確認方法は `PHONE_CHECKLIST.md`)。
- **5hから、テストは既定でローカルHTTPサーバー(`http://127.0.0.1:<空きポート>/`)経由で実行します。** サーバーは各テストが自分で起動・終了します(`lib_http.js`。127.0.0.1のみ・読み取り専用・ディレクトリの外は配らない)。理由: ヘッドレスChromiumの `file://` では、再読み込みのあとに保存データが全部消えることがあるため(下の「環境の記録」)。従来方式は `VIL_SERVE=file` で再現できます。

## 実行方法
```
cd tests && npm i && npx playwright install chromium
# 今の index.html(リポジトリ直下)を確認
bash run_all.sh                       # 5e/主要動線(76項目) + 5f専用 + 5g専用 + 5h専用(洞窟の入口・再読み込み)
# 前の版と比べる(同じ操作で保存データ・文言が一致するか)
bash run_all.sh /path/to/5gのindex.html /path/to/5fのindex.html   # 比較(22場面)・5hの修正が5gの不具合を検出できるかの確認・前の版との互換も確認
```
- 別の場所のファイルを確認するときは `INDEX=/path/to/index.html bash run_all.sh`
- 結果は `tests/results/run_日時.txt` に、対象のSHA-256・サイズ・node・playwright・chromium の版・**実行方式(http/file)・再読み込みの回数と保存データ消失の回数**つきで保存される。
- 再読み込みの検証回数は `VIL_RELOAD_N`(既定30)。最後に、参考として `file://` 方式でも同じ回数を実行する(合否には数えない。`VIL_REF_FILE=0` で省略)。

## 環境の記録:`file://` で保存データが消える現象(5h)
- 同じ操作(ホーム → 町づくり → 資材づくり → 再読み込み×2)を30試行して、再読み込みで保存データのキーが消えた試行の数:
  - `http://`(ローカルHTTPサーバー): **0 / 30 試行(再読み込み60回で消失0)**
  - `file://`(従来方式・参考): **8 / 30 試行**(消えたキーは elemVil・elemVilBk・elemWorld。町のデータだけが消えたことはない)
- 町を開く前の版(main)でも `file://` では同様に消えることを5gで確認済み。ヘッドレスChromium+`file://` の環境要因と判断している。ただし**実機では未確認**。
